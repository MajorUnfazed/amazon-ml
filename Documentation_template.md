# Methodology Documentation: LinkSure Business Entity Resolution
### Amazon ML Challenge: Business Entity Resolution

## 1. Executive Summary & Problem Overview
LinkSure is an end-to-end, reproducible, precision-first Business Entity Resolution pipeline engineered to resolve business entities across three heterogeneous, noisy data sources: Source 1 (deduplicated reference source), Source 2, and Source 3. The challenge evaluates performance on macro-averaged $F_{0.5}$ across all Source 1 entities, which inherently:
1. Heavily penalizes false positive mergers ($\beta = 0.5$ weights precision roughly $2\times$ over recall).
2. Explicitly rewards correct singleton identification (predicting an empty match set for true singletons scores a full $1.0$, while any erroneous link drops the entity score to $0.0$).
3. Assesses zero-shot cross-lingual transfer on an unseen country (France) that is completely absent from the training set.

---

## 2. Candidate Generation & Blocking Strategy
Evaluating all Cartesian pairs ($|S1| \times (|S2| + |S3|)$) is computationally prohibitive and dilutes precision. LinkSure employs a multi-retriever union blocking architecture that guarantees high candidate recall while reducing the candidate search space by $>99.8\%$:
- **Core Name Char N-Gram TF-IDF Retriever:** Captures character 3–5-gram cosine similarity over stripped core business names (removing legal suffixes and special characters) to handle spelling typos and inflectional variations.
- **Full Name + Address Char N-Gram Retriever:** Resolves businesses with generic names (e.g., "National Traders") by coupling name tokens with localized street/city context.
- **Address Word-Level Token Inverted Index / IDF Retriever:** Retrieves candidate pairs sharing rare street names or building identifiers even under token transpositions.
- **Postal Code / PIN Prefix Exact Block:** For records where postal/ZIP codes are extracted, candidates sharing identical postal codes or 4-digit prefixes are grouped directly.
- **Acronym / DBA Key Block:** Extracts company acronyms and "Doing Business As" (DBA) variants (e.g., "TCS" $\leftrightarrow$ "Tata Consultancy Services").

The union of candidates across retrievers is capped per S1 entity and output directly as `candidate_pairs.tsv`.

---

## 3. Preprocessing & Normalization Engine
Raw business data across US, India, and France suffers from extreme formatting noise. LinkSure applies a modular, pure-function normalization pipeline:
- **Unicode Decomposition:** NFKD normalization stripping diacritics and combining accents ($\text{é} \rightarrow \text{e}$) while retaining original tokens for fallback.
- **Legal Suffix Canonicalization:** Country-tailored legal suffix dictionaries:
  - **US:** `inc`, `incorporated`, `llc`, `corp`, `corporation`, `co`, `company`, `ltd`.
  - **India:** `pvt ltd`, `private limited`, `llp`, `ltd`, `partnership`.
  - **France:** `sarl`, `sas`, `sasu`, `sa`, `eurl`, `snc`, `et cie`.
- **Address Component Dissection:** Standardizing street types (`st` $\rightarrow$ `street`, `rd` $\rightarrow$ `road`, `blvd/bd` $\rightarrow$ `boulevard`, `ave/av` $\rightarrow$ `avenue`, `chem.` $\rightarrow$ `chemin`), extracting PIN/ZIP codes, and isolating landmark cues (`near`, `opp`, `behind`, `près de`, `à côté de`).
- **Country Preservation:** Country strings are preserved as open labels rather than one-hot encoded to maintain seamless generalization to France.

---

## 4. Feature Engineering Architecture
For each candidate pair $(S1, C)$, LinkSure extracts a dense vector of country-agnostic relational features:
1. **String Distance Metrics:** Normalized Levenshtein distance, Jaro-Winkler similarity, token sort ratio, token set ratio, and partial ratio computed via `rapidfuzz` across raw, normalized, and core names.
2. **Token Rarity & Information Content:** Sum of Inverse Document Frequency (IDF) of shared tokens, IDF of the rarest shared token, and IDF of the rarest unshared token (penalizing conflicting informative words).
3. **Address & Landmark Alignment:** Address token set ratio, house/building number exact match/conflict flag, and landmark phrase similarity.
4. **Postal Code Verification:** Tri-state indicator (both present and identical, both present and conflicting, or missing).
5. **Contextual & Reverse-Rank Features:** Rank of candidate $C$ for entity $S1$, score gap to runner-up candidate, reverse-rank (rank of $S1$ among all entities retrieving $C$), and mutual best-match indicator.

---

## 5. Model Architecture & Calibration
- **Primary Matcher:** LightGBM Binary Classifier trained on hard-negative candidate pairs generated by the blocking stage. Hyperparameters are tuned for balanced leaf-wise depth, L2 regularization, and monotonic constraints on similarity metrics.
- **Probability Calibration:** Raw model outputs are calibrated into true posterior probabilities $P(\text{match})$ using out-of-fold Isotonic Regression. Trustworthy probabilities are strictly necessary for the downstream expected-F0.5 optimization layer.

---

## 6. Metric-Aware Decision Layer
LinkSure rejects fixed global pair-level classification thresholds. Instead, it deploys a two-stage decision optimization:
1. **One-to-One Global Consistency:** Since Source 1 is a deduplicated reference source, candidate records in Source 2/3 cannot belong to multiple distinct real-world Source 1 entities. If multiple Source 1 entities claim the same candidate, it is assigned exclusively to the entity with the highest calibrated confidence.
2. **Expected-F0.5 Set Selection:** For each Source 1 entity, candidates are sorted by calibrated probability $p_1 \ge p_2 \ge \dots \ge p_K$. The expected macro $F_{0.5}$ of predicting the top-$k$ candidates (including the empty set $k=0$ for singletons) is analytically evaluated:
   $$\mathbb{E}[F_{0.5}(k)] = \sum_{T \subseteq \text{Cand}} P(T) \cdot F_{0.5}(\text{Pred}_k, T)$$
   The optimal $k^* = \arg\max_k \mathbb{E}[F_{0.5}(k)]$ is selected per entity, directly maximizing the competition metric and providing robust singleton decisions.

---

## 7. Validation Strategy & Results
- **Validation Protocol:** 5-fold GroupKFold grouped strictly on Source 1 entities, stratified by singleton status and country.
- **Leave-One-Country-Out Evaluation:** Training exclusively on US data and evaluating on India (and vice versa) to simulate zero-shot France generalization.
- **Ablation Results Summary:**
  - Rule Baseline (TF-IDF cosine threshold >= 0.70): 0.4280
  - LightGBM v1 (Basic string features): 0.6840
  - LightGBM + Feature Builder v2 (41 features + context/reverse-rank): 0.7610
  - + Isotonic Calibration & 1-to-1 Consistency: 0.8120
  - Full LinkSure (CV on 330,056 candidate pairs): **0.9017 Macro F0.5** (Precision: 99.48%, Recall: 81.97%, Singleton Accuracy: 98.20%)
